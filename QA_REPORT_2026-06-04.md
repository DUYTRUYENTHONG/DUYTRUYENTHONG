## Findings

### P0 - Public API leaks sensitive seed data when Supabase is not configured

Evidence:

- `GET /api/app-data` returns `seedData` directly when Supabase env is missing.
- Response exposed seed user passwords (`admin123`, `sales123`, `content123`, `editor123`), user contact details, consultation lead data, account inventory, and integration connector data.
- `GET /api/leads` also returns seed consultation leads publicly when Supabase is not configured.

Code:

- `src/app/api/app-data/route.ts:23`
- `src/lib/seed.ts:413`
- `src/lib/seed.ts:603`
- `src/app/api/leads/route.ts:51`
- `src/app/api/leads/route.ts:68`

Recommendation:

- In `GET /api/app-data`, never return raw `seedData` to unauthenticated users. Use `sanitizePublicAppData(seedData)` or fail closed in production.
- In `GET /api/leads`, require authenticated workspace access for all environments, or return an empty public response.
- Consider removing plaintext seed passwords from public seed payloads entirely.

### P1 - Lead POST succeeds but does not persist when Supabase is not configured

Evidence:

- Before `POST /api/leads`: 1 lead.
- Valid POST returned 201.
- After `POST /api/leads`: still 1 lead.

Impact:

- Public UI can tell users "lead saved" while no server-side persistence exists if deployment misses Supabase env.

Code:

- `src/app/api/leads/route.ts:160`

Recommendation:

- If Supabase is required for production lead capture, return a clear failure when not configured.
- Or implement fallback persistence for the MVP mode.

### P1 - Missing image assets cause 404 and blank cards in sales portfolio

Evidence from browser HAR on `/s/duy` mobile:

- 404: `/images/brand-bg.png`
- 404: `/images/dtt-logo-service.png`

Code:

- `src/lib/seed.ts:734`
- `src/lib/seed.ts:747`

Recommendation:

- Add the missing assets under `public/images`, or update seed references to existing images such as `/images/brand-board.png` or `/images/dtt-logo-services.png`.

### P2 - Cookie consent banner obstructs key UI on mobile and appears in workspace

Evidence:

- On `/contact` mobile, banner covers phone/Zalo/email fields.
- On `/bio/gon-xinh-daily` mobile, banner covers product CTA area.
- On `/workspace` mobile/desktop, banner covers dashboard/sidebar even though workspace is internal.

Code:

- `src/app/layout.tsx:31`
- `src/components/page-analytics-tracker.tsx:145`
- `src/components/page-analytics-tracker.tsx:148`
- `src/app/globals.css:655`

Recommendation:

- Do not render `PageAnalyticsTracker` for internal routes such as `/workspace`.
- On mobile public pages, use a compact bottom sheet/bar or reserve bottom spacing so it does not cover forms and CTA buttons.

### P2 - Workspace login fails without `WORKSPACE_SESSION_SECRET`

Evidence:

- Without `.env.local`, `POST /api/workspace/session` returned 500:
  `Thieu cau hinh server: WORKSPACE_SESSION_SECRET.`

Code:

- `src/app/api/workspace/session/route.ts:73`
- `.env.example:12`

Recommendation:

- Treat this as required deployment configuration.
- Add deployment check documentation or a startup guard for production.
